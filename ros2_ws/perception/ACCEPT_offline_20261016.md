# 两个交付模型的离线精度验收：多次构建取最差（感知组，2026-10-16）

对应：`issues` 3.7 (2)“精度是硬门……整机侧要看验收报告”；4.1“本机构建流程下，PD-16 承诺类在多次构建抖动中的最差仍满足”、INT8 单独加严；4.3 补登两项（验收引擎指纹、构建抖动幅度记录）。

> 说明：这是**离线**部分。PD-16 实机矩阵还没跑（实机与消防场区未到位），口径缺口见第六节。出处写法同前：`D:` 指感知内部记录 `notes/DECISIONS.md`，`E:` 指感知仓库 `evidence/` 下的文件。

## 一、一句话

- 两个模型各在 1.8（开发机）上用正式构建工具**从头独立重建 3 次**，每次都评测，每条线取最差的那次：**active12（608 窗口，FP16）过，coco80（INT8）过**。
- **评测集里大多数图不走产品路径**：active12 的评测集 must93、val579 里约八成图的长宽比放不进 608 窗口，产品会拒收它们，评测工具对这些图用的是居中补边。所以“全集过”说明的是模型（经评测工具）与教师一致，**不等于产品路径过**。产品真正会处理的那 116 张图（must93 的 16 张都在 val579 里）上，服务里的推理模块与评测工具用同一个引擎逐张对过：输入、原始输出逐张相同；掩码只差裁剪取整（框边约 1 像素）和 6 个检出上各 1 个像素（原因推断是浮点舍入，未核实）；把这 116 张换成服务的掩码重算，仍然过。
- coco80 只在 COCO val2017 上评，没有消防场区集，人、车也没有单独的逐类门限（第六节第 4 点）。
- 构建抖动：active12 三次里 a1、a3 原始输出逐张相同；a2 的原始输出与它们不同，最终检出在 29 / 93、209 / 579 张图上完全相同，其余图上同一输出格分数相同（差 0）、框最多差 2.49 像素，真值命中状态变化 0 个。coco80 INT8 三个引擎文件各不相同，**评测输出逐字节相同**。

## 三、判定线

**active12**（我方内部精度门，用户 10-09 / 10-10 定；对 PT 教师）：
- (a) must93：不贴线的真值新漏检 0 个（框和掩码分别算）。
- (b) 贴线真值（教师分数离 0.25 不到 0.05，或 IoU 离 0.5 不到 0.05）最多翻转 3 个，且翻转的都还在原处（分数 ≥ 0.20、IoU ≥ 0.45）。
- (c) val579 逐类：每类“少找到几个”“多报了几个”各有上限（B_m 一组：少找到 6/3/3/3/3/3/3/3/3/3/8/4、多报 11/8/5/6/8/5/4/4/7/8/19/9；合计少找到 ≤ 18、多报 ≤ 35；坑少找到 ≤ 2 且不贴线新漏 0；可通行区域多报 ≤ 5）。

**coco80**（与模型师任务书的验收线相同；对官方 PyTorch，单位是百分点的下降）：
- 全 80 类 Box mAP50-95 ≤ 1.0、Mask mAP50-95 ≤ 1.0；
- 导航 25 类：Mask AP 平均下降 ≤ 1.5、任何一类 ≤ 3.0；
- 置信度 0.25、NMS IoU 0.7 下，导航 25 类的 Box 准确率 / 检出率、Mask 准确率 / 检出率各下降 ≤ 2.0。

## 七、附：服务里的推理模块与评测工具逐张对照

- 做法：开发工具 `perception_a12_parity` 把评测用的同一批图一张一张喂给服务里的推理模块（同一个引擎 `6a7eb8c3…`），记下输入张量、原始输出、最终发布的检出；再与评测工具的输出逐张比。
- 结果：服务按窗口规则收的图 must93 16 张、val579 116 张（must93 这 16 张都在 val579 里，合计 116 张不同的图；其余图的长宽比放不进 608 窗口，服务拒收，与模型师的窗口规则逐张一致）。这些图上**输入张量、原始输出逐张相同**；检出的类别、分数、框逐个相同。
- 差别只在掩码：服务按 Ultralytics 的取整规则把掩码裁到像素框，评测工具裁到浮点框，框边约差 1 像素；另有 6 个检出在大掩码轮廓上差 1 个像素（推断是浮点舍入，还没逐级核实）。把这 116 张图换成服务自己的掩码（其余图仍用评测工具的掩码）重算 active12 验收：仍然过（val579 掩码真检出还多 1 个）。这不等于全集的服务精度；连续来帧的路径、方形输入回归还没对过。
