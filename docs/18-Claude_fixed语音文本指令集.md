### 0.2 一条指令会得到哪几种回复

| 回复 | 什么时候出现 | 在哪里看 |
|---|---|---|
| **即时回复** | 收到指令立刻回答（复述「好的,去X」、查询答案、拒绝原因） | commx 显示的 `reply_text`；`state/voice_turn` 第一条记录；机器人喇叭 |
| **执行结果** | 执行端（P3 任务 / 对象库 / 录制、P1 运动）回执后补一句（如「已保存X…」「X没有完成: 原因」） | `state/voice_turn` 第二条记录（`layer=teach_result` 或 `command_result`）；喇叭 |
| **不出声** | 急停、站立、趴下（安全旁路直达底盘，不复述） | 只能看底盘动作或 `cmd/chassis/ctrl/ack` |
| ⚠️ **只回「收到」** | 意图被识别、指令发了出去，但系统没有专门的复述话术 | 是否真的执行要看本册各节的说明 —— 有不少「收到」之后执行端直接丢弃 |

⚠️ 只有任务、对象库、录制、运动四类执行端的拒绝会被播报。**模式（C 类）、声光（D 类）、云台（E 类）的执行端拒绝不播报**：即时回复说了「收到」，执行端失败也不会再有第二句。

### 0.3 现场麦克风与云端文本的区别

| 项 | 现场麦克风 | 云端文本 / 云端语音（含 commx） | HMI 文本 |
|---|---|---|---|
| 删除围栏、关闭围栏 | 🚫 拒绝：「这个操作不允许从这里发起」 | ✅ 一句即删 | 🚫 同麦克风 |
| ASR 纠错（同音字修正） | 有 | 文本没有；云端语音有 | 没有 |
| 「不是对机器人说的话」过滤 | 有（旁人闲谈会被忽略） | 文本没有（文本一律视为对机器人说的）；云端语音有 | 没有 |

其余指令在各通道的识别与回复相同。

### 0.4 全局规则（所有类别通用）

1. **一问一答，不追问、不二次确认**（`99` U147）。缺名字、缺米数、缺方向一律直接拒绝并说明正确说法，不会反问「去哪里？」。
2. **含急停词的话一律先急停**：「急停 / 停止 / 紧急停止 / 立刻停下 / 停 / stop」在整句里**任何位置出现**都会触发急停（按子串匹配，安全优先）。所以：
   - ⚠️「暂停任务」「停一下」「停车」都是**急停**，不是暂停；暂停任务请说「暂缓任务 / 等一下 / 先别巡了」；
   - 名字里不要用「停」字（如「停车场」），否则说到这个名字就会急停；
   - 例外：「停止跟踪」「停止扫描」「停止环视」归云台，不触发急停。
3. **名字规则**（航点、路径、围栏）：2–12 个字；「一号测试点」与「1号测试点」是同一个名字；名字里的空格、标点忽略。
4. **礼貌前缀可以带**：现在、请、请你、麻烦、帮我、立刻、立即、马上、赶紧、尽快、快点、海卫、机器人、好的、然后、接着、那就、再 —— 例「现在请去1号测试点」「海卫，马上返航」。
5. **听不懂时**：多数情况回「没太听清,请再说一遍」；部分情况**完全不回复**（见 §11）。
6. **录制期间**只接受：退出 / 取消 / 打点 / 查录制状态 / 所有查询 / 会话应答 / 闲聊；其余一律拒绝「正在录制X, 录制期间只能用键盘控制机器人. 要结束请说退出录制」（📄，见 §6.3）。
7. **定时**只能加在「去航点 / 巡逻 / 返航 / 回充电桩」前面；删除、改名不能定时。

## 2. B 类 · 导航任务

> 实测时无定位：所有新任务都被 P3 以「定位失效, 现在不接受新任务」（`E_DEGRADED`）拒绝。即时回复（「好的,去X」）是 P4 的复述，**执行结果以随后的第二句为准**。有定位时，被受理的任务在执行失败时会补播「X没有完成: 原因」（📄，见附录 A.3）。

### 2.1 去航点（B01）

**正确说法**：去X · 前往X · 去往X · 导航到X · 导航去X · 走到X · 到X去 · 去航点X · 🔎 到X（不带「去」，例「到3号测试点」→「好的,去3号测试点」）；尾部可带「一趟 / 一下 / 看看 / 那边 / 吧」；可带礼貌前缀与定时前缀（§2.6）。

| 情形 | 即时回复 ✅ | 执行结果 ✅ |
|---|---|---|
| 去1号测试点 · 前往2号测试点 · 导航到3号测试点 · 到1号测试点去 · 去往返航终点站 · 去1号测试点一趟 · 现在去2号测试点 | 「好的,去1号测试点」（名字按说的复述） | 「定位失效, 现在不接受新任务」<br>📄 其它拒绝：「电量过低, 现在不接受新任务」；受理后失败：「去X没有完成: {现在拿不到定位 / 找不到目标点或路径 / 路线生成失败 / 运动模块没有确认路线 / 途中导航失败 / 任务检查没有通过}」 |

路线规则：航点在某条路径 5 米内 ⇒ 就近进入路径、沿路径过去；离航点比离路径近 ⇒ 直走；不属于任何路径 ⇒ 直走。

### 2.6 定时任务

**可定时的指令**：去航点 · 巡逻 · 返航 · 回充电桩。时间写法：
- 相对时间（须带「后 / 之后 / 以后 / 过后」）：30秒后 · 5分钟后 · 2小时后 · 2个小时后 · 半小时后 · 一个半小时后；
- 绝对时间：下午3点 · 15:30 · 晚上八点半 · 明天14点 · 明天下午3点 · 后天上午9点15分 · 今晚8点 · 中午12点。
- 范围：相对时间一天以内；日期一周以内；同一时刻只能排一个任务。

定时说法由规则解析，识别为 B01 / B02 / B08 / B09 并带上时间（实测全部如此）。注册表里的 **B03 `patrol_schedule`（定时巡逻）** 只在规则解析不了时间时才会被走到，实测「三天后去1号测试点」→ B03 →「没找到你说的那条路径, 换个说法试试」（答非所问，见 §2.7）。

### 9.1 确认词与「再说一遍」（补测）

## 13. 每条指令的全部可能回复（按代码逐分支核对）

> **为什么有这一节**：前面各节的「实测回复」只是测试当时那一种机器状态下的回复（无定位、底盘锁定、三合一离线、没有任务、没有围栏、不在录制）。同一句话在别的状态下会有别的回复。本节按代码逐个分支列出**每条指令所有可能的回复**及其触发条件。
>
> **核对范围**：编排器 `p4_agent/runtime/turn_orchestrator.py`（全部分支）、各请求构建器（`task_request` / `task_control_request` / `motion_intent_request` / `mode_request` / `teach_request` / `geo_request`）、执行端回执播报 `ack_speech.py`、查询 `state/status_answers.py` · `state/query_data.py` · `query/sources_g43_g47.py` · `state/time_sync_answer.py`、`configs/chitchat.yaml` · `configs/query_templates.yaml`，2026-11-14 代码。
>
> **不会出现的话术**：`configs/restate_templates.yaml`（「前往X,规划N公里…」等复述模板）、`dialog/speak_stop.py`（「已停止喊话」等）、`failsafe/rotation_reject.py`（「旋转已阻塞…」）在运行时都**没有接入**，不会被说出来。
>
> 写法：「…」是逐字话术，`{X}` 是填入的值；「→」后是执行端回执后补的第二句。
