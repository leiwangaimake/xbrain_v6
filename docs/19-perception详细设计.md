> ★★ `perception` 与 `common/` 的关系是**单向依赖**：perception 引 `common/`，🚫 `common/` 不引 perception 的任何头。

## 2. ★★★ 33 ms 实时预算的逐段分解

### 2.1 两条流水线，不是一条

> ★★ **相机 30 fps（33 ms）与点云 10 Hz（100 ms）是两个不同的节拍。**
> ★ 把点云的逐点处理放进 33 ms 的相机回路，等于**每帧算一遍只有 10 Hz 才会变的东西**，成本乘 3 且无任何收益。

```text
   ┌─ 相机线程（30 fps，周期 33 ms）────────────────────────────────────────┐
   │  A 取图 → B 预处理 → C TRT 推理 → D 后处理 → E MOT → F 深度/wpos      │
   │                                    → G 走廊求值（读点云快照）         │
   │                                    → H 序列化与发布                   │
   └───────────────────────────────────────────────┬───────────────────────┘
                                                   │ 读（无锁双缓冲，见 PRC-11）
   ┌─ 点云线程（10 Hz，周期 100 ms）───────────────┴───────────────────────┐
   │  P1 收包 → P2 ROI 裁剪 → P3 地面分割 → P4 体素/栅格 →                 │
   │  P5 走廊的 LiDAR 分量（三条 band 的 d_lidar_m）＋ sectors 分桶 →       │
   │  P6 发布 rt/lidar/{scan, points, grid}                                │
   └───────────────────────────────────────────────────────────────────────┘
```

### 2.2 ★★ 相机线程的逐段预算（周期上界 **33 ms**）

> ⚠️★★★ **下表是【设计预算】，🚫 不是实测值。**
> ★ 实测归 `scripts/perf/perception_stage_timing.py`（待建），本册**只留判据与脚本路径**，🚫 不回抄数字 —— 抄进来的数一定会过期。

| 段 | 内容 | 预算 | P99 判据 |
|---|---|---|---|
| **A** | 取图：RGB + depth 到 GPU 可用（含驱动拷贝） | 4 ms | `A ≤ 6 ms` |
| **B** | 预处理：letterbox + 归一化（GPU） | 2 ms | `B ≤ 3 ms` |
| **C** | TRT 推理（YOLOv11n） | 8 ms | `C ≤ 12 ms` |
| **D** | 后处理：decode + NMS | 2 ms | `D ≤ 3 ms` |
| **E** | MOT 关联（`id` / `age` / `lost`） | 2 ms | `E ≤ 3 ms` |
| **F** | 深度取样（`dist_m` / `bpos`）＋ `wpos` 内插 | 2 ms | `F ≤ 3 ms` |
| **G** | 走廊求值（`bands` 的深度分量 ＋ `dir_free` ＋ 合成） | 3 ms | `G ≤ 4 ms` |
| **H** | 序列化与发布（RT 精简版 ＋ 通用面完整版 ＋ ROS 2） | 3 ms | `H ≤ 5 ms` |
| **合计** | | **26 ms** | ★ **周期 P99 ≤ 33 ms · max ≤ 50 ms** |
| **余量** | | **7 ms** | ★ 余量是**结构性要求**，🚫 不得被新功能吃光 |

| # | 约束 | 变异体 |
|---|---|---|
| **PRC-10** | ★★★ **相机线程内 🚫 不得有任何阻塞 I/O、🚫 不得有动态分配的热路径**。全部输出缓冲在初始化阶段一次性分配 | **PMT-5** |
| **PRC-11** | ★★ 点云快照用**双缓冲 ＋ 原子指针交换**交给相机线程；🚫 相机线程不得持锁等待点云线程 | **PMT-6** |
| **PRC-12** | ★ 单帧超预算（> 33 ms）**不得丢帧重来**，按已完成的部分发布并在 `degraded` 中如实登记；★ 连续 `over_budget_frames`（缺省 **10**）超预算 ⇒ 发 `warn` 事件 | **PMT-7** |
| **PRC-13** | ★★★ 发布 `put` 一律 **非阻塞**（Q1 的 `congestion_control = drop`）。🚫 `rt/lidar/points` 绝不用 `block` | `11` §2.3 逐字「阻塞 perception 的发布线程 → 整条感知流水线停摆」 |

### 2.3 ★★ 点云线程的逐段预算（周期上界 **100 ms**）

| 段 | 内容 | 预算 | 依据 |
|---|---|---|---|
| **P1** | 收包 + 反序列化（值拷贝，DDS-5） | 1.0 ms | `11` §3.10.1「点云反序列化 per-point 归 C++」 |
| **P2** | ROI 裁剪 | 0.5 ms | 同上 |
| **P3** | 地面分割 | 1.0 ms | 同上 |
| **P4** | 体素下采样 / 投影 2D 栅格 | 2.0 ms | 同上 |
| **P5** | 走廊 LiDAR 分量（三条 band 一遍出）＋ `sectors` 分桶 | 1.0 ms | `11` §3.1.4 ⑪ |
| **P6** | 三路序列化与发布（`scan` / `points` / `grid`） | 3.0 ms | ★ base64 编码是主项 |
| **合计** | | **8.5 ms** | ★ 相对 100 ms 周期余量充足 |

> ★★★ **`scan` / `points` / `grid` 三者由本线程从【同一份点云】一次生成**（`11` §3.10.3 逐字「三者由 perception 从同一份点云一次生成，不得分别计算」）。
> ★ 三者的 `frame_ts` / `frame_mono` **必须相同**，取**点云采集时刻**，🚫 不是发布时刻。

| # | 约束 | 变异体 |
