## 1. cmd/teleop：可以直接沿用包内裸格式

**结论：可以。** Qt 直接沿用参考客户端的 key、六个字段和 `device=keyboard_cloud`，**不要**自行加前缀或外层。

| 项 | 约定 | 代码依据 |
|---|---|---|
| 连接 | 连目标机器人的通用面 router `tcp/<机器人IP>:7447`（gj-001 为 `tcp/192.168.188.200:7447`）。zenoh `client` 模式，关闭组播 scouting | router 监听 `192.168.188.200:7447`；`session_factory.py` PLANE_GEN |
| key | **裸 `cmd/teleop`**。不加 `xbrain/{rid}/` 前缀，发到 `xbrain/{rid}/cmd/teleop` 没有任何订阅者 | `p1_motion/runtime/main_wiring.py` `CMD_TELEOP_TOPIC = "cmd/teleop"`；通用面没有配置 namespace |
| 外层 | **没有** `v/rid/ts/seq/src/data`。业务体就是顶层 JSON | P1 `_on_teleop` 直接在顶层读 `d.get("device")`、`d.get("deadman")`、`d.get("axes")` |
| 目标机器人 | 由所连的 router 决定，消息里没有 rid。一个 session 只连一台机器人 | 各机器人的 router 互不相连 |
| 回执 | 无 ack | 遥控通道本身没有 ack key |

**机器人实际读取的字段：**

| 字段 | 机器人怎么用 |
|---|---|
| `device` | 必须是 `keyboard_cloud`（闭集，`teleop/state.py` `TELEOP_DEVICES`）。闭集外的值整帧丢弃，并打 warn 日志 |
| `deadman` | `true`：持有遥控权。`false`：交还遥控权，机器人立即不再按该源行驶 |
| `axes.vx` / `axes.vy` / `axes.wz` | 归一化量，每轴先截到 [-1, 1]。速度 = 轴值 × 语音设定速度（前后与横移用 `move_speed`，默认 0.5 m/s；转向用 `turn_speed`，默认 0.6 rad/s），见 `teleop/velocity.py`。`wz` 左转为正，`vy` 左移为正。机器人**接受连续值和多轴组合**；参考客户端只发 ±1、单轴，是客户端自己的做法，不是协议限制 |
| `client_id` / `client_seq` / `buttons` | **当前不读**。照发即可，但机器人不靠它们去重或排序，所以同一时刻只能有一个云端键盘客户端 |

**时序：**

- 机器人按收到的时刻计龄，**400 ms** 收不到新帧就视为失效并停车（`_TIMEOUT_MS["keyboard_cloud"] = 400`）。请按 **10 Hz** 持续发送，三轴全 0 也要发。
- 三轴全 0 且 `deadman=true`：原地停住，仍持有遥控权。持有期间自主任务一律不动。
- 退出时发一帧 `deadman=false`。交还之后，自主任务才能再驱动机器人。

**⚠️ 安全约束，必须告知操作员**（用户裁决 U150，`nav_wiring.py` `_teleop_unconditional`）：

- `keyboard_cloud` **无条件执行**，只受急停和底盘限幅约束。
- 速度门、避障、围栏、旋转许可、定位、航向检查**都不作用于它**。
- 它也**不限于录制期间**：任何时候只要 `deadman=true`，都会驱动机器人。

**实际消息**（参考客户端 `frame.py` 生成，机器人原样接受）：

```json
{"device":"keyboard_cloud","client_id":"cloud-kbd-01","client_seq":118,"deadman":true,
 "axes":{"vx":1.0,"vy":0.0,"wz":0.0},"buttons":{"mark":false,"release":false}}
```

## 2. 判断「录制已开始」

### 2.1 开始指令

- 路径和围栏用同一个通道：发文本到 `xbrain/{rid}/cmd/voice_text`（与其它文本指令相同）。
- 路径示例：「现在开始录制3号路径」。围栏示例：「现在开始录制东门围栏」。
- 名称规则：名称以「路径 / 路线 / 线路 / 环线」或「围栏」结尾，2～12 个字，不能与已有同类对象重名（`slots/record_slots.py`）。

### 2.2 机器人对开始指令的回报

一次开始最多两条 `state/voice_turn`，都没有 `cmd_id`，用 `intent` 加 `layer` 识别：

| 第几条 | `layer` | 含义 | 可否据此开放键盘 |
|---|---|---|---|
| 第 1 条（该轮自己的记录） | `record_rule` | `verdict=rejected`：机器人在发出命令前就拒绝了（没带完整名称、名字长度不对、重名、已在录制），**之后不会有第 2 条**。`verdict=accepted`：只表示开始命令已发出，`reply_text`=「好的,开始录制X. 请用键盘控制机器人移动, 说退出录制结束并保存」 | **否** |
| 第 2 条（开始的结果） | `teach_result` | 机器人跑完开始检查后发出。`verdict=accepted`、`reply_text`=「已开始录制X」：录制已开始。`verdict=rejected`：没有开始，`reject_code` 为原因码，`reply_text` 为原因句 | **是，只看这一条** |

- 两条的 `intent` 都是 `record_route_start`（路径）或 `record_fence_start`（围栏），`asr_text` 都是所发文本。第 1 条为「没带名称」「已在录制」时 `intent` 固定为 `record_route_start`，因为此时还判断不出类型。
- 第 2 条照抄第 1 条的 `channel`、`session`、`asr_raw`、`asr_text`、`intent`，`turn_id` 是新的。
- 文本指令不要求语音（`require_tts_reply=false`）时，两条照样都发，`reply_kind=none`。

第 2 条被拒时的原因码与原因句（`ack_speech.py`）：

| `reject_code` | `reply_text` |
|---|---|
| `E_TEACH_QUALITY` | 现在不能开始录制: 定位不是RTK固定解 |
| `E_UNHEALTHY` | 现在不能开始录制: 设备状态不允许移动（或：没有可用的非语音急停通道） |
| `E_LOW_BATTERY` | 现在不能开始录制: 电量不足 |
| `E_LOCKED` | 现在不能开始录制: 硬件急停按下了 |
| `E_BUSY` | 有任务正在执行, 现在不能开始录制 |
| `E_TEACH_BUSY` | 已经在录制了, 不能开始新的录制 |
| `E_NAME_CONFLICT` | X这个名字已经有了, 请换个名字再录制（名字在发出与检查之间被占用） |

**实测**（gj-001，室内无 RTK，U165 上机后）：

```
「开始录制」（缺名）
+0.00 xbrain/gj-001/state/voice_turn {"intent":"record_route_start","verdict":"rejected","reject_code":null,
       "reply_text":"录制指令要带上完整名称, 比如: 现在开始录制1号路径, 或: 现在开始录制东门围栏","layer":"record_rule",...}

「现在开始录制测试9号路径」
+0.00 xbrain/gj-001/state/voice_turn {"turn_id":"vt-625dee632f7b","intent":"record_route_start","verdict":"accepted",
       "reply_text":"好的,开始录制测试9号路径. 请用键盘控制机器人移动, 说退出录制结束并保存","layer":"record_rule",...}
+0.48 xbrain/gj-001/state/voice_turn {"turn_id":"vt-6cd3d29d49df","intent":"record_route_start","verdict":"rejected",
       "reject_code":"E_TEACH_QUALITY","reply_text":"现在不能开始录制: 定位不是RTK固定解","layer":"teach_result",...}
```

开始成功的那条（`verdict=accepted`、「已开始录制X」）室内没有 RTK 测不到，形状与上面被拒的那条相同，由单测核对（`tests/p4_agent/runtime/test_ack_speech.py`）。

**Qt 的判据：**

1. 发出开始文本后，看 `intent ∈ {record_route_start, record_fence_start}` 的记录。
2. 第 1 条 `verdict=rejected`：未开始，显示 `reply_text`，结束等待。
3. 第 1 条 `verdict=accepted`：继续等 `layer="teach_result"` 的那条。`accepted` 才开放键盘；`rejected` 显示原因。机器人通常 1 s 内回结果，建议超时设 5 s，超时按未开始处理。
4. 不要按 `reply_text` 的文字判断，也不要只按 `verdict` 而不看 `layer`。

> 另外，`cmd/teleop` 本身不要求录制已开始：开始录制时没有遥控源在线，只记 `warn: no_driver`，照样开始（`teach/session.py` 检查 6）。所以按上面的判据先开始后开放、或先开放后开始，机器人都接受。

> 需要录制实时状态（点数、长度、已用时间）时，机器人另有裸 key `state/teach`（1 Hz，状态变化时立即发；录制中 `session.state="recording"`）。上面的判据不需要它。

## 3. 结束、保存、取消

### 3.1 怎样结束

**只能用文本或语音。**

- HMI 的录制是只读的，没有结束按钮（W4 裁定）。
- 云端没有专用 key。
- 录制期间「结束 / 取消 / 查询录制」这几类文本**可用**：录制期间放行的只有这几类以及查询、闲聊（`turn_orchestrator.py` `_REC_ALLOWED`）。

| 操作 | 文本 | 机器人动作 |
|---|---|---|
| 结束并保存 | 「退出录制」「录制完成」「结束录制」「录完了」，或带名字的「3号路径录制完成」「3号路径录完了」「结束3号路径录制」 | 以开始时的名字直接保存，不追问。带名字时，名字必须与正在录的一致，否则回复「正在录制的是A, 不是B. 要结束请说: A录制完成」，不执行 |
| 取消 | 「取消录制」「放弃录制」，或带名字的「取消3号路径录制」 | 直接丢弃，不确认（U137）。带名字时规则同上 |
| 查询 | 「录了几个点」「录制状态」 | 回复「正在录制X, 已经录了N个点, 长M米」 |

### 3.2 Q 释放遥控后录制会怎样

- **录制不受影响**：继续计时，继续按 1 Hz 采点。机器人不动，与上一点不足 0.5 m 的采样不记，所以点数不涨。
- 不暂停，不保存，不结束：P3 的录制不依赖遥控源（`teach/runtime.py` 中没有遥控丢失导致的状态迁移）。
- 所以「遥控已退出」不等于「录制已结束」，Qt 必须分开显示。
- 可以重新开启键盘接着开，也可以不开键盘直接发「退出录制」保存。

### 3.3 结果怎样反馈

一次结束会有**两条** `state/voice_turn`：

1. 结束指令本轮：`layer="record_rule"`，`verdict=accepted`，`reply_text`=「好的,退出录制, 正在保存X」或「好的,取消录制X」。只表示指令已发出。
   - 若本轮被拒（没有在录制，或带的名字不是正在录的），则 `verdict=rejected`，原因在 `reply_text`，**之后不会有第 2 条**，录制照旧进行。
2. P3 处理完后：`layer="teach_result"`，新 `turn_id`，`intent` 抄自原轮（路径结束 `record_route_stop`，围栏结束 `record_fence_stop`，取消 `record_route_cancel`）。

| 结果 | 第 2 条 `verdict` | 第 2 条 `reply_text` | 之后 `state/teach` |
|---|---|---|---|
| 保存成功（路径） | `accepted` | 「已保存X, 共N个点, 长M米」 | `idle` |
| 保存成功（围栏） | `accepted` | 「已保存X, 共N个顶点. 围栏已保存但未启用, 需要时请说启用X」 | `idle` |
| 轨迹不合格，不保存，会话关闭（路径不足 2 点、围栏不足 3 顶点、自交、面积过小） | `rejected`，`reject_code=E_TEACH_GEOMETRY` | 「录制已退出, X没有保存: 原因」 | `idle` |
| 写入失败（例如名字被别处占用），**数据保留** | `rejected`，`reject_code` 为真实原因（如 `E_NAME_CONFLICT`） | 「X没有保存: 名字已被占用. 录制数据还在, 请说保存为新的名字, 或者放弃录制」 | `finalizing`（再发「保存为新名字」或「放弃录制」） |
| 取消 | `accepted` | 「已取消录制X, 录到的N个点已丢弃」 | `idle` |

- 原轮不播报（文本指令不要求语音）时，第 2 条照样发。
- 判断保存是否成功，请看第 2 条的 `verdict`，不要解析中文。
- 机器人上同时保留裸 key `cmd/teach/ack`（带 `session_id`，详情见 `detail.saved` / `detail.applied`），供需要细节时使用。

### 3.4 不经 Qt 结束的情况（Qt 也需要关闭键盘）

| 情况 | 反馈 |
|---|---|
| 机器人本地麦克风说「退出录制」 | 同 3.3 的两条 voice_turn，`channel="mic_local"`、`session="local"`。**请不要按 channel 过滤**，否则会漏掉 |
| 到达录制时长上限（默认 **180 min**，可配置；暂停中也计时） | 到时前 10 min、1 min 各一条提醒；到时自动以开始时的名字保存。每次都会发一条 `state/voice_turn`（`layer="teach_result"`，`asr_text=""`，`intent=null`，归在发起录制的通道下）和一条事件 `event/{info|warn}/teach`（`detail.kind` = `teach.time_warning` / `teach.expired`，`detail.result` = `saved` / `save_failed` / `discarded`） |

两种情况下，`state/teach` 都会从 `recording` 变为 `idle`。写入失败时是 `finalizing`。

### 3.5 Qt 收尾的建议判据

- **关闭键盘控制：**
  - 收到 `layer="teach_result"` 且 `intent ∈ {record_route_stop, record_fence_stop, record_route_cancel}` 的记录（`verdict` 任意）；
  - 或收到事件 `teach.expired`（任意 `result`）。
  - ⚠️ 不能按「`layer="teach_result"` 就关」：开始的结果（`intent=record_*_start`）也是这个 layer；到时提醒与到时自动收尾的 voice_turn 都是 `intent=null`、提醒与已保存都是 `verdict=accepted`，两者只能靠事件的 `detail.kind`（`teach.time_warning` / `teach.expired`）区分，提醒时不要关键盘。
- **显示「已保存」：** 结束结果 `verdict=accepted` 且 `intent` 是 `record_route_stop` / `record_fence_stop`；或 `teach.expired` 的 `detail.result=saved`。
- **不要**把「遥控退出」或第一条 `record_rule` 回复当成保存完成。
- 若你方也订了 `state/teach`：`session.state` 离开 `recording` 即录制已停止，可作兜底。

## 附：与本答复相关的其它前提

- Qt 必须每秒发 `xbrain/{rid}/heartbeat/qt`。
  - `cmd/teleop` 和 `cmd/voice_text` **都不刷新**云端在线计时。
  - 只开键盘、只发文本时，机器人 20 s 判云端断开，30 min 后自动返航。
  - 详见 `update_cloud.md` §1。
- 录制期间语音「停 / 急停」不生效（U45）。停车请发三轴全 0，或用 `cmd/estop`。
