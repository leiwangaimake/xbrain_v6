# 云端语音 / 文本交互契约 v1.0（XBRAIN V6，云端集成版）

> **用途**：本文给甲方云端软件的开发同学，用来把「云端语音 + 文本控制机器人」的能力集成进甲方官方云端软件。
> 功能上**等同于我方调试客户端 `commx`**（`/opt/commx`，见 §11）：云端把文本或语音送到机器人，机器人按 `18` 指令集理解并执行，再把「听到了什么、理解成什么、执行结果、答复文本」回报给云端。
>
> **版本**：v1.0 · 2026-10-26 · 以 2026-10-26 在 `gj-001`（.1.26 整机）上实测通过的实现为准。
> **契约真源**：`11` §8.7.3（`audio/voice_in`）· §8.7.5（`cmd/voice_text`）· §8.7.6（`state/voice_turn`）· `99` U92（音频格式与 188 网）。本文与真源冲突时以真源为准，并请告知我方修订本文。
> **实现位置**（机器人侧）：`xbrain/p4_agent/runtime/cloud_input.py`（两个入口）· `xbrain/p4_agent/runtime/voice_turn.py`（审计记录）。

## 1. 全局约定

### 1.1 连接

| 项 | 约定 |
|---|---|
| 传输 | Zenoh **1.9.0**（与机器人同版本），云端以 **`client`** 模式连接，不运行 router |
| 地址 | 机器人通用面 router：`tcp/<机器人 LAN2 IP>:7447`。当前整机 `gj-001` = **`tcp/192.168.188.200:7447`**（甲方 188 自组网，`99` U92） |
| 发现 | 关闭组播 scouting，直接按地址连接 |
| 实时面 | 🚫 不连接 `7449`（机器人内部实时面，只监听回环） |
| 多机器人 | 每台机器人一个独立 session，key 第二段 `{rid}` 各不相同 |

### 1.2 key 与 `rid`

- 本文全部 key 形如 `xbrain/{rid}/...`，`{rid}` = 机器人 ID（`[a-z0-9_-]{1,32}`，大小写敏感）。当前整机 `rid = gj-001`。
- 三个 key 都**由云端直接在机器人 router 上收发**，机器人侧由 `p4_agent` 直接处理（不经网关转译，`11` §2.2）。

### 1.3 报文外层

| 方向 | 报文形状 |
|---|---|
| 云端 → 机器人（`cmd/voice_text`、`audio/voice_in`） | ★ **两种都收**：① **裸业务体**（本文 §3/§4 的字段直接放顶层，commx 即如此）；② v2.0 通用外层 `{v, rid, ts, seq, src, data}`，业务体放 `data`。机器人检测到 `data` 是对象即按外层解包。**推荐云端与 v2.0 其它 key 保持一致，用外层** |
| 机器人 → 云端（`state/voice_turn`） | ⚠️ **裸业务体**（§5 字段直接在顶层，**没有** `v/rid/ts/seq/src/data` 外层）。这是当前实现，与 v2.0 其它状态 key 不同，解析时请注意 |

- 编码：UTF-8 JSON，中文原样（不转义）。
- 时间：业务字段里的 `issued_ts` 是 Unix 秒（float），只作审计；**所有超时都由机器人用本机单调钟判定**，云端时钟不影响任何判定。

## 2. key 全量表

| Key | 方向 | 频率 / QoS | 用途 |
|---|---|---|---|
| `xbrain/{rid}/cmd/voice_text` | 云端 → 机器人 | 事件；可靠 | **文本指令**：一条消息 = 一句话 |
| `xbrain/{rid}/audio/voice_in` | 云端 → 机器人 | 流；可靠，**发布端拥塞策略用 BLOCK** | **语音指令**：一句话切成多帧 PCM，最后一帧 `eos=true` |
| `xbrain/{rid}/state/voice_turn` | 机器人 → 云端 | 每轮交互一条（事件） | **一轮交互的结果**：听到的原文、纠错后文本、意图、执行结论、答复文本 |

★ **答复只在机器人身上出声**：机器人的语音答复由三合一载荷模块（GZH-2）设备内 TTS 合成播放，主控板拿不到音频，**云端听不到**。云端要展示答复，**唯一来源是 `state/voice_turn.reply_text`**。

## 3. `cmd/voice_text` —— 文本指令

### 3.1 报文

```json
{
  "cmd_id": "cloud-t-000123",
  "channel": "cloud",
  "text": "向前走0.3米",
  "session_hint": "cloud",
  "require_tts_reply": true,
  "issued_ts": 1792958281.6
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | ✅ | 要执行的一句话。首尾空白会被去掉；**空串被拒**（不产生任何记录） |
| `channel` | string | ✅ | 闭集 `cloud` \| `wecom` \| `hmi`。**甲方云端固定填 `cloud`**。决定 `18` 的通道准入（如 H07/H08 只允许 `cloud` / `wecom`）与会话槽 |
| `cmd_id` | string | 建议 | 云端自定义的请求 ID，机器人写进日志（`ref=`）便于对账；建议全局唯一 |
| `require_tts_reply` | bool | — | 缺省 `true`：机器人**出声答复**。`false`：不出声、不占喇叭，答复**只写进** `state/voice_turn.reply_text` |
| `session_hint` | string | — | 建议值，机器人以 `channel` 为准；可填与 `channel` 相同的值 |
| `issued_ts` | number | — | Unix 秒，审计用 |

### 3.2 行为要点

1. **文本视为「已对机器人说话」**：不需要唤醒词、称呼（`16` §5.2.1 补记）。
2. 文本**不经 ASR 后处理**（没有音近错误）。`state/voice_turn` 里 `asr_raw` = `asr_text` = 所发文本。
3. 一条消息只放**一句**指令。多条指令请分多条消息依次发送，**等上一条的 `state/voice_turn` 回来再发下一条**（见 §6.1）。
4. ⚠️ 云端输入框请对中文做好「删除 / 回退」处理。2026-10-26 实测出现过：终端里显示的是「向左**转**20度」，实际发出的是「向左20度」（编辑时丢字），机器人按收到的文本判为 `unknown`。

## 4. `audio/voice_in` —— 语音指令

### 4.1 音频格式（唯一接受的格式，`99` U92）

| 项 | 值 |
|---|---|
| `codec` | **`pcm_s16le`**（有符号 16 位小端，裸 PCM，无文件头） |
| `sample_rate` | **16000** |
| `channels` | **1**（单声道） |
| 每帧时长（建议） | **100 ms**（= 3200 字节 PCM），commx 默认值 |

🚫 其它格式（opus、48 kHz、立体声等）**一律拒收，机器人不做重采样**。请在云端完成采集→重采样→单声道→s16le 转换。

### 4.2 报文（每帧一条）

```json
{
  "stream_id": "cloud-v-000124",
  "chunk_seq": 0,
  "codec": "pcm_s16le",
  "sample_rate": 16000,
  "channels": 1,
  "channel": "cloud",
  "session_hint": "cloud",
  "eos": false,
  "payload_b64": "AAABAP7/..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `stream_id` | string | ✅ | **一句话一个 ID**，该句所有帧相同；不同句必须不同。非空 |
| `chunk_seq` | integer | ✅ | 帧序号，**从 0 开始、逐一递增、不得跳号** |
| `codec` / `sample_rate` / `channels` | — | ✅ | 见 §4.1，每帧都要带，逐帧校验 |
| `channel` | string | ✅ | 闭集 `cloud` \| `wecom`（`hmi` 没有音频上行）。**甲方云端固定 `cloud`**。同一句中途不得改变 |
| `eos` | bool | ✅ | **只有最后一帧为 `true`**。机器人收到 `eos=true` 才把整句送去识别 |
| `payload_b64` | string | ✅ | 该帧 PCM 的 Base64。解码后字节数必须是**偶数**（整数个采样）。允许空串 `""`：只用来带 `eos=true` 的收尾帧可以不带音频 |
| `session_hint` | string | — | 同 §3.1 |

### 4.3 断句与上传方式

- **按句上传**：云端用 VAD（语音活动检测）在本地切好一句话，再把这一句切帧连续发出，最后一帧 `eos=true`。**不要**持续推流、也不要把多句塞进一个 `stream_id`。
- commx 的 VAD 参数可作参考：能量阈值 300、句尾静音 500 ms、最短语音 200 ms、句首预留 300 ms（pre-roll，防止吃掉第一个字）、单句上限 25 s。
- 带宽：一句 5 s 的话约 160 kB，188 自组网实测约 8.7 Mbit/s，按句连发即可（`99` U92）。
- 发布时请用**可靠传输 + BLOCK 拥塞策略**：丢一帧整句作废（§4.4）。

### 4.4 机器人侧的组句规则与上限

| 规则 | 机器人行为 |
|---|---|
| 首帧 `chunk_seq ≠ 0` | 整句拒收（`stream_starts_mid_sentence`） |
| 跳号（例如 3 之后来了 5） | ★ **整句丢弃**（`chunk_gap`）。缺一段的句子转写出来是另一句话、可能是另一条指令，所以宁可「什么都没发生」 |
| 重复帧（序号小于期望值） | 忽略，不报错（可靠传输重投可能出现） |
| 单句时长 > **30 s** | 整句丢弃（`utterance_too_long`） |
| 单句时长 < **200 ms** | 不送识别（`utterance_too_short`） |
| 某句超过 **3 s** 没有新帧 | 回收该句（视为客户端中途掉线） |
| 同时未结束的句子 > **4** 句 | 拒收新句（`too_many_streams`），不挤掉旧句 |
| 格式字段不对 | 该帧拒收（`bad_codec` / `bad_sample_rate` / `bad_channels` / `bad_channel` / `bad_payload` / `odd_pcm_bytes`） |
| 必填字段缺失或类型不对（如 `chunk_seq` 不是整数、`eos` 不是布尔、`stream_id` 为空），或报文不是 JSON 对象 | 该帧拒收（`bad_field` / `not_an_object`） |
| 同一句中途 `channel` 改变 | 拒收（`channel_changed`） |

⚠️ **以上拒收都只记在机器人日志里，不会产生 `state/voice_turn`**。云端看到的现象是「发了一句话，没有任何回报」。云端集成时建议：发完 `eos` 后 **12 s 内没收到 `state/voice_turn`** 就提示「机器人未响应」，并让我方查日志（日志里带上述原因码与 `stream_id`）。

### 4.5 语音与文本的两个区别

★ **云端语音一律出声答复**：语音入口没有 `require_tts_reply` 字段，机器人固定按 `true` 处理。只想要文本答复、不想占用机器人喇叭时，请用 `cmd/voice_text` 并设 `require_tts_reply=false`。

另一个区别是「是不是在对机器人说话」：

云端语音**不享受**文本的「已对机器人说话」待遇（`16` §5.2.1 补记）：它是远端的一支麦克风，可能录进旁人说话。机器人会判断这句话是不是在对它说：
- 祈使句、指令句（「站起来」「向前走零点三米」「打开探照灯」）一般都能通过；
- 闲聊、残句会被判为**旁听**（`verdict=unknown`，`layer=overheard`），不执行、不答复，但**仍会回一条** `state/voice_turn`。

## 5. `state/voice_turn` —— 一轮交互的结果

### 5.1 何时发

机器人对**每一轮**都发一条：本地麦克风、`cmd/voice_text`、`audio/voice_in` 三个入口一视同仁，在动作指令发出之后发。旁听的轮次也发。§4.4 中被拒收、没进入识别的语音**不发**。

### 5.2 报文（裸业务体，无外层）

下例为**云端语音**一轮（文本一轮没有 `latency_ms`，且 `asr_raw` = `asr_text` = 所发文本）：

```json
{
  "turn_id": "vt-b9e1551967af",
  "session": "cloud",
  "channel": "cloud",
  "asr_raw": "机器人向左转15度",
  "asr_text": "机器人向左转15度",
  "corrections": [],
  "bypass": null,
  "intent": "turn_left",
  "slots": {"angle_deg": 15.0},
  "auth_level": "L1b",
  "verdict": "accepted",
  "reject_code": null,
  "reply_text": "好的,左转",
  "reply_kind": "stream",
  "layer": "long_phrase",
  "ts_mono": 12345.678,
  "latency_ms": {"asr": 260}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `turn_id` | string | 本轮 ID（`vt-` 开头）。运动类指令与机器人内部运动意图帧的 `turn_id` 逐字一致 |
| `session` | string | `local` \| `cloud` \| `wecom`：本轮属于哪个会话槽。云端文本和云端语音同属 `cloud`（同一对话，文本问的确认可以用语音答） |
| `channel` | string | `mic_local` \| `cloud` \| `wecom` \| `hmi`：本轮从哪个入口进来。★ **云端只处理 `channel=cloud` 的记录**，`mic_local` 是机器人本机麦克风听到的（例如现场有人说话） |
| `asr_raw` | string | ★ 识别原文（后处理之前）。文本入口 = 所发文本 |
| `asr_text` | string | ★ 后处理之后的文本，机器人据此理解。**两栏都请展示**：分得清是「识别听错」还是「纠错改错」 |
| `corrections` | array | 纠错明细 `{layer, from, to, score / distance}`；无纠错为 `[]` |
| `bypass` | string \| null | `estop` \| `prone` \| `stand` \| `null`：本轮是否命中安全旁路（急停 / 趴下 / 站起来，不经大模型直接执行） |
| `intent` | string \| null | 理解出的意图名（`18` 指令集里的英文名，如 `move_forward`、`turn_left`、`ptz_scan`） |
| `slots` | object | 意图参数，如 `{"distance_m": 0.3}`、`{"angle_deg": 15.0}`；无参数为 `{}` |
| `auth_level` | string \| null | 确认等级 `L0` \| `L1a` \| `L1b` \| `L2` \| `L3`（`18` §13.1） |
| `verdict` | string | ★ **结论**，闭集见 §5.3 |
| `reject_code` | string \| null | 拒绝时的错误码（`11` §13 闭集），如 `E_CHANNEL_DENIED` |
| `reply_text` | string \| null | ★ **机器人的答复文本**。出声与否都会填写 |
| `reply_kind` | string | `stream`（已在机器人上出声）\| `none`（未出声：`require_tts_reply=false`、旁听、或本轮无答复） |
| `layer` | string \| null | 由分类器哪一层判定，闭集：`long_phrase`（关键词长短语命中）· `session_state`（会话状态，如回答确认）· `large_class`（大类判定）· `overheard`（判为旁听）· `unknown`（交给大模型 / 判不出）；安全旁路轮次为 `null`。用于区分两种 `verdict=unknown` |
| `ts_mono` | number | 机器人本机单调钟秒数，**只用于同一机器人内排序**，不可与云端时钟比较 |
| `latency_ms` | object | 可选，只含实际量到的项（云端语音目前只有 `asr`） |

### 5.3 `verdict` 闭集

| `verdict` | 含义 | 云端建议展示 |
|---|---|---|
| `accepted` | 已执行 / 已答复 / 已下发动作 | 「已执行：`reply_text`」 |
| `pending_confirm` | 需要二次确认（L2 类，例如「取消任务」），机器人在等回答 | 弹出「`reply_text`」并提供【确认】【取消】，见 §6.3 |
| `rejected` | 被拒绝（通道不允许 / 确认被否 / 确认超时 / 安全条件不满足等），原因见 `reject_code` 与 `reply_text` | 「未执行：`reply_text`」 |
| `unknown` | 没听懂（`layer=unknown`），或判为不是在对机器人说话（`layer=overheard`） | 「未识别：`asr_text`」 |

- **安全旁路轮次**（急停 / 趴下 / 站起来，`bypass` 非空）：`intent`、`layer`、`reply_text` 都是 `null`，`reply_kind=none`。机器人直接执行，不播报答复；云端请根据 `bypass` 字段展示「已急停 / 已趴下 / 已站起」。
- **反问也是 `accepted`**：参数不全时（例如只说「前进」），机器人反问「要走多远? 请说一个米数」，`verdict=accepted`、`intent=move_forward`、`slots={}`，反问内容在 `reply_text`。此时**没有下发任何动作**，等操作员补一句带数字的话（例如「0.3米」或「向前走0.3米」）。

⚠️ `accepted` 表示**机器人已经受理并下发**，不保证物理动作已经完成。例如运动指令受理后，还可能被底盘侧保护（锁定、超时等）中止，详见 §8。

## 6. 交互时序

### 6.1 文本一轮

```
云端                               机器人 (p4_agent)
 │  cmd/voice_text {text, channel=cloud}
 │──────────────────────────────────▶│ 准入 → 理解 → 执行/答复
 │                                    │ (出声答复：机器人喇叭)
 │◀──────────────────────────────────│ state/voice_turn {verdict, reply_text ...}
 │  展示结果，再发下一条
```

- 典型耗时：关键词直达的指令 < 1 s；需要大模型理解的句子 2～8 s。commx 的等待上限是 **12 s**，可作参考。
- 一个会话同一时间只处理一轮；连续快速发多条会按到达顺序排队执行。**建议等回报后再发下一条。**

### 6.2 语音一轮

```
云端: 采集 → VAD 断句 → 重采样 16k 单声道 s16le
 │  audio/voice_in  chunk_seq=0..N-1 (eos=false)
 │  audio/voice_in  chunk_seq=N      (eos=true)
 │──────────────────────────────────▶│ 组句 → ASR → 纠错 → 理解 → 执行/答复
 │◀──────────────────────────────────│ state/voice_turn
```

### 6.3 需要二次确认的指令（L2）

1. 云端发「取消任务」→ 回报 `verdict=pending_confirm`，`reply_text` 是确认提问。
2. 云端在 **8 s 内**、在**同一会话**（`channel=cloud`，文本或语音都行）发「确认」或「取消」：
   - 肯定词：`是` / `对` / `确认` / `好的` / `可以`（`18` I01）
   - 否定词：`不是` / `不` / `算了` / `不用`（`18` I02）
3. 回报 `accepted`（已执行）或 `rejected`（已取消）。超过 8 s 未答 → 下一轮回报 `rejected`（确认超时）。
4. 答复既不是肯定也不是否定时，机器人继续等待，并再次回报 `pending_confirm`。

### 6.4 急停

- 文本或语音发「急停」「停止」「紧急停止」「立刻停下」「停」「stop」（`18` A01，配置词表），命中安全旁路，**最高优先级**，不经大模型。回报 `bypass=estop`、`verdict=accepted`。
- ⚠️★ **急停是「包含即触发」**：句子里**只要出现**上述任一词（包括单字「停」），就按急停处理，并且优先于其它一切理解（安全设计：宁可误停，不可漏停）。所以「停止喊话」「停止任务」「别停下」这类说法**都会触发急停**，而不会执行字面意思。需要这些功能时请用不含「停」的说法：退出喊话说「**退出喊话**」，取消任务说「**取消任务**」或「**结束任务**」。
- 云端软件的急停**按钮**请走 v2.0 的独立急停 key `xbrain/{rid}/cmd/estop`（见 `json格式文件_qt端v2.0.md`），不要依赖文本通道。两条路径并存、互不替代。

## 7. 喊话（B 模式）期间的规则（`11` §8.7.4，安全相关）

| 时段 | 云端麦克风音频应发往 |
|---|---|
| 平时（对话 / 控制） | `xbrain/{rid}/audio/voice_in`（本文 §4） |
| 进入喊话模式后 | ★ **改发 `xbrain/{rid}/audio/broadcast`**（v2.0 已冻结的喊话流），**不要再发 `voice_in`** |
| 退出喊话后 | 改回 `voice_in` |

- 理由：喊话时操作员对着麦克风说的话是**喊给现场的**，不能被当成指令。否则喊一句「退出喊话」，就会把系统自己喊出喊话模式。
- 机器人侧兜底：喊话模式下收到 `channel=cloud` 的 `voice_in`，**整句丢弃、不识别**。
- ★ **喊话期间唯一可用的控制通道是文本**：退出喊话请发 `cmd/voice_text` `{"text":"退出喊话","channel":"cloud"}`。
- ⚠️ **不要用「停止喊话」**：它含「停止」，会先命中急停（§6.4），机器人急停而不是退出喊话（2026-10-26 实测）。`11` §8.7.5 的示例文本恰好是「停止喊话」，该示例与急停词表冲突，已报我方修订。

## 8. 能说什么

- 全部可用指令见 `18-语音文本指令集.md`（含 `18-A` / `18-B` / `18-C` 扩展），包括运动、站立 / 趴下、云台、灯光与警笛、模式、任务、查询等。
- 通道限制：部分指令只允许特定通道（`18` 各条目「通道」列）。`channel=cloud` 不允许的指令，回报 `verdict=rejected`、`reject_code=E_CHANNEL_DENIED`，答复「该指令不支持当前通道」。

### 8.1 运动指令的说法（2026-10-26 实测）

| 动作 | 推荐说法（必须带数字和单位） |
|---|---|
| 前进 / 后退 | 「向前走0.3米」「后退0.5米」 |
| 原地左转 / 右转 | 「机器人向左转15度」「向右转30度」 |
| 左移 / 右移 | 「向左移0.2米」「向右移0.2米」 |
| 站立 / 趴下 | 「站起来」「趴下」 |

- ★ **必须说出数字和单位**（米、厘米、度）。只说「前进」机器人会反问「走多远」。「挪一挪」「走两步」这类说法**不会**被当成距离（防止大模型编造一个距离去真实运动）。
- 「步」不是距离单位。另外语音说「向左转十步」时，「转十」曾被纠错成「环视」，变成了云台指令。转向请说「度」。
- 单条指令上限：网关层允许距离 ≤ 20 m、角度 ≤ 720°；**当前测试模式下执行端只执行 ≤ 3 m、≤ 180°**，超过的整条**不执行**（不会截断成别的动作）。注意此时 `state/voice_turn` 仍是 `accepted`、机器人仍答「好的,右转」（见 §9.1 最后一行），请云端把单条指令控制在 3 m / 180° 以内。

## 9. 拒绝与错误

| 现象 | 原因 | 云端处置 |
|---|---|---|
| 有 `state/voice_turn`，`verdict=rejected`，`reject_code=E_CHANNEL_DENIED` | 该指令不允许当前通道 | 提示「云端不支持此指令」 |
| `verdict=rejected`，`reject_code` 为其它 `E_*` | 安全 / 状态条件不满足（如机器人锁定、录制中等），`reply_text` 有说明 | 展示 `reply_text` |
| `verdict=unknown`，`layer=unknown` | 没听懂 | 提示换个说法；语音可对照 `asr_raw` 判断是不是识别错了 |
| `verdict=unknown`，`layer=overheard` | 语音被判为不是在对机器人说话 | 用祈使句重说，或改用文本 |
| 发了语音，**没有任何回报** | ① §4.4 格式 / 组句被拒，或太短（< 200 ms）；② 喊话模式下发了 `channel=cloud` 的语音（§7，整句丢弃）；③ 识别结果为空（只有噪声 / 静音）；④ 机器人语音识别服务异常或超时 | 检查格式与帧序、当前是否在喊话模式；把 `stream_id` 给我方查日志 |
| 发了文本或语音，**没有任何回报**（格式都对） | ⑤ 机器人处理该轮时内部出错（会记日志，但当前实现不补发回报）；⑥ 机器人积压超过 16 轮未处理，新的一轮被丢弃 | 把 `cmd_id` / `stream_id` 给我方查日志 |
| 发了文本，**没有任何回报** | `text` 为空、`channel` 不在闭集、报文不是 JSON，或 `rid` / key 写错 | 检查报文与 key |

### 9.1 已知问题与修复记录（2026-10-26）

| 现象 | 原因 | 状态 |
|---|---|---|
| 问「现在电量多少」没有任何回报 | 机器人侧电量查询读错字段，该轮内部出错 | ✅ 已修（`99` U96）：答「当前电量N%，剩余续航约X公里」；无电池在位时答「读不到」 |
| 问「现在几点」回报 `rejected` | 「现在几点」不在查询关键词里 | ✅ 已修（`99` U96）：读机器人系统时间播报并写入 `reply_text`；关键词「几点了 / 现在几点 / 几点钟 / 现在时间 / 现在什么时候 / 今天几号」 |
| 某一轮内部出错时没有任何回报 | 异常未被收口 | ✅ 已修：改为回报 `verdict=rejected`、`reject_code=E_INTERNAL` |
| 「停止喊话」「停止任务」「停止跟随」「停止记录」「暂停」等触发急停 | 急停词表含「停止」「停」，包含即触发（§6.4） | ✅ 已按用户裁决删除这些说法（`99` U96）；请用「退出喊话」「取消任务 / 结束任务」「别跟了」「结束录制」「暂缓任务 / 等一下 / 先别巡了」。说「停」仍然急停 |
| 「右转360度」只转 180° | 测试模式执行端上限截断（§8.1） | ✅ 已修：超限整条不执行 |
| 运动指令被网关或执行端拒绝 / 中止（如未解锁、超限、堵转），`voice_turn` 仍是 `accepted` | `voice_turn` 只反映 p4 的受理结论；后续拒绝目前没有回报给云端的契约 key | ⚠️ 待设计 |

## 10. 测试期临时说明（2026-10-26 基本动作测试阶段，交付前会撤销）

> ⚠️ 本节描述的是**当前测试阶段**的特殊状态，**不是正式契约**。正式版本会随感知与 RTK 定位就绪而恢复标准流程，届时另行通知。

1. **基本动作测试模式**：为测试前后、左右转、左右移，机器人的部分安全门暂时关闭（不依赖感知与 RTK，按底盘里程计闭环）。**期间没有避障**，每个动作前**现场必须有人确认周围净空**。速度：前后 0.2 m/s、横移 0.15 m/s、转向 0.3 rad/s。
2. **解锁**：机器人底盘程序每次启动都处于「超时锁定」，必须先解锁才能运动。目前的解锁方式是 commx 的「解锁」命令。它直接向机器人发 `cmd/chassis/ctrl` `{action:"enable"}`，并且要求操作员二次确认。**这条路径不是给云端的正式接口**：正式的云端解锁入口（经网关、带 L2 确认凭据，`11` §9.3.4 E-1）尚未落地。云端集成**本期请不要实现解锁**，测试时由我方用 commx 解锁。
3. **站立后自动切换导航模式**：说「站起来」后，机器人自动把底盘切到导航模式（数秒），之后才接受运动指令。
