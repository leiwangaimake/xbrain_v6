★★★ **「不后退」🚫 不等于「不减速」。**

### 5.2 `margin_base` 怎么进入判据 —— **只进一次**

```text
  ★★★ 唯一进入点

    r_inflate = r_robot + margin_base + k · v_infl             ← margin_base 在这里，且只在这里
       │                                    ↑ 见下方 RNS-FC-13（v0.2 新裁决）
       v
    膨胀后栅格  occ_inf[cell] = 2  若任一 occ==2 的原格在 r_inflate 内
       │
       v
    走廊判据    沿航向 ψ 的【中心线】逐格取样，判 blocked
                ★★★ 🚫 中心线上【不再】加任何横向半宽、不再加第二次 margin
```

★★★ **【新裁决 · `RNS-FC-1`】`margin_base` 只在膨胀核里计入一次，走廊射线是【零宽中心线】。**

| 项 | 内容 |
|---|---|
| 裁什么 | ★ 射线投射在**膨胀后**栅格上做，射线本身**无宽度**；🚫 不得再对射线加 `±r_inflate` 的横向半宽 |
| ★★ 为什么 | ★ 膨胀的**数学含义**就是「把机体缩成一个点，把障碍胀大 `r_inflate`」—— 这是 Minkowski 和的标准用法。★★ 再加一次半宽 = **把 `margin_base` 算两遍** ⇒ 有效余量变成 **2.0 m** |
| ★★★ 后果链（不是理论担忧） | ★ 营区道路宽 **4–6 m**（`11` §3.2.1 B6），机体居中半宽 **2.0–3.0 m**。★★ 双重计入后 4 m 路上的有效需求 ≈ `r_robot + 2.0 + k·v` > 半宽 ⇒ ★★★ **窄路绕行恒不可行** ⇒ 这是一条**永远红的判据**（失效形态 ②）⇒ 它的最终形态必然是**有人去调小 `margin_base`** —— 而 `margin_base` 是 U54 拍板值，调它等于改需求 |
| ★ 失效方向 | ★ 本裁决**不放宽任何余量**：单次计入后机体外缘到障碍仍恒 ≥ `margin_base + k·v` ≥ 1.00 m（`RNS-U3`）⇒ **中性** |
| ★★★ **推翻它需要什么证据** | ★ 证明膨胀核的实际作用半径**小于** `r_inflate`（例如量化取整方向错、或核形状用了 4-邻接近似而非欧氏圆）。★ 那时的正确修法是**修核**（见 §5.3），🚫 **不是**在射线上补一层半宽 —— 补半宽会把一个**可定位的核缺陷**变成一个**不可定位的余量叠加** |

★★★ **【新裁决 · `RNS-FC-13`（v0.2）】`k` 项里的速度取 `v_infl = max( |v_current| , v_req )`。**

| 项 | 内容 |
|---|---|
| ★★ 本条修的是什么 | ★★★ **v0.1 的一处自相矛盾（W8 对抗验收抓出）**：本节式子照抄 `12` §4.2b.3 的逐字 `k · v_current`，而 §5.4 的因果链 `RNS-FC-6` 却断言「`v_max ↓` ⇒ `r_inflate ↓`」。★★ `v_current`（本拍实测/上一拍已发出的速度）与 `v_max`（本拍速度门授权上限）**不是同一个量** —— 速度门刚跌档的那一拍，`v_max` 已经是 0.5 而 `v_current` 仍是 2.0，⇒ **那条因果链在 (a) 支上当拍不成立**。v0.1 把两个量当成一个写了 |
| 裁什么 | ★ `v_infl = max( \|v_current\| , v_req )`，其中 `v_req` 按 `RNS-FC-7` ＝ 本拍 `v_max` |
| ★★ 为什么取 max 而不是二选一 | ① ★ 只取 `v_current`：机器人**将要**跑到 `v_req` 时膨胀量偏小（还没加速，核先按慢速给）⇒ **朝快失效**；② ★ 只取 `v_req`：正在从 2.0 减速的那几拍，`v_req` 已是 0.5 而机体**实际**还在 2.0 上滑行，膨胀量偏小 ⇒ **同样朝快失效**；③ ★★★ 取 max ⇒ **两条都堵**，且它恒 ≥ 原式 ⇒ 相对 `12` §4.2b.3 逐字只会**更保守**，🚫 不放宽任何余量 ✓ CON-07 |
| ★ 对因果链的诚实修正 | ★★ `v_max ↓` ⇒ **`L_min` 当拍即降**（它只含 `v_req`）；★ 而 `r_inflate` 要**等机体真的减下来**才降（`v_current` 跟随需若干拍）。⇒ ★★★ **降速使绕行成为可能这条链仍成立，但 (a) 支是【滞后】的，不是【当拍】的** —— §5.4 的框图已按此改写，🚫 不要再读成两支同时下降 |
| ★★★ **推翻它需要什么证据** | ★ 实测证明减速段内 `max()` 使膨胀过度以致「本该能绕的窄路绕不过去」。★ 那时的正解是**按制动模型给 `v_infl` 一个随拍衰减的上界**（仍恒 ≥ 真实速度），🚫 **不是**退回单取 `v_req` |

★ **变异体（`A-INF-2`）**：注入「`v_current = 2.0` 且同拍 `v_max = 0.2`」⇒ 断言 `r_inflate` 按 **2.0** 算（`r_want = r_robot + margin_base + k×2.0`）。★ 写成 `k · v_req` 的实现取到 0.2 ⇒ **必须变红**。
★ **反向变异体（`A-INF-3`）**：注入「`v_current = 0`（静止起步）且 `v_max = 2.0`」⇒ 断言 `r_inflate` 仍按 **2.0** 算。★ 写成 `k · v_current` 的实现取到 0 ⇒ **必须变红**。
★★ **两条缺一不可** —— 只写其中一条时，另一个单边实现全绿通过。

### 5.3 ★★★ 【新裁决 · `RNS-FC-2`】膨胀核量化**向上取整**

> ★★★ **本条填的是 `12` §4.2b.4 `G-2` 的一个真实空洞。**
> ★ `G-2` 逐字只要求「膨胀核**按 `r_inflate` 量化到有限档位（如 5 档）**并预先构造」，**未规定取整方向**。

| 项 | 内容 |
|---|---|
| 裁什么 | ★★★ 量化一律 **`ceil`**：选中的档必须是**不小于** `r_inflate` 的最小档。🚫 不得四舍五入、🚫 不得 `floor` |
| ★★ 为什么 | ★★★ 四舍五入会让**约一半**的取值落到「实际膨胀半径 < `r_inflate`」⇒ 机体外缘到障碍的真实间距 **< 1.00 m** ⇒ **直接违反 U54 规则 ③**，且**无任何报错**（fail-silent）。★ `floor` 则是 100% 违反 |
| ★ 连带约束 | ★★ **最小档必须 ≥ `r_robot + margin_base`**（即 `v = 0` 时的 `r_inflate`）；★ 最大档必须 ≥ `r_robot + margin_base + k · common.spec.max_vx_mps`。★ 两端都不满足 ⇒ 启动自检不通过 ⇒ **绕行分支关断**（§7.1 **第五支**），🚫 不是整栈不启动（与 `12` §12.1 末补注对 `RCG-1` 的处理同构） |

| ★★★ **推翻它需要什么证据** | ★ 实测证明 `ceil` 使窄路绕行不可用（4 m 路上恒无可行走廊）。⚠️ 但那时的正确出路是**加密档位**（`kernel_levels` 由 5 增到 10，量化误差减半），🚫 **不是**改取整方向 —— ★ 加密的成本是预构造内存（每档一个核），常数级 |

★★★ **`A-INF-1a` / `A-INF-1b`（本节的可证伪断言 —— 替代 `RNS-U3` 那条按构造不可反驳的话）**
