# Qt前端任务枚举

## 1. Zenoh key任务入口

主控电脑作为zenoh router,Qt client 将所有任务统一发布到：

```text
robots/{robot_id}/task/request
```

`{robot_id}`发布时替换为具体机器人 ID。机器狗后端zenoh client 统一订阅该 key，读取 JSON 中的 `task_type`，再转给运动、导航、报警、录像或音频模块。

机器狗向 Qt 返回任务反馈：

```text
robots/{robot_id}/task/ack
robots/{robot_id}/task/progress
robots/{robot_id}/task/result
```


方向如下：

| Key | 方向 | 用途 |
|---|---|---|
| `robots/{robot_id}/task/request` | Qt → 机器狗 | 下发任务请求 |
| `robots/{robot_id}/task/ack` | 机器狗 → Qt | 确认接收或拒绝请求 |
| `robots/{robot_id}/task/progress` | 机器狗 → Qt | 上报长任务进度 |
| `robots/{robot_id}/task/result` | 机器狗 → Qt | 上报任务最终结果 |



## 2. 全部任务枚举（具体JSON格式在json格式文件.md的第二章，对应以下5个）

| 编号 | `task_type` | 中文名称 | 用途 | 主要数据来源 | 后端处理模块 |
|---|---|---|---|---|---|
| T01 | `GOTO_KEYPOINT` | 导航 | 按 `waypoints` 数组顺序导航到一个或多个关键点，可关联录制路径 | 下发计划按钮、计划中的路点、关键点库、录制路径库 | 任务管理、导航 |
| T02 | `STOP_TASK` | 停止任务 | 停止当前或指定任务，并使机器人安全停止 | 停止按钮、目标任务 ID、停止原因 | 任务管理、导航、运动控制 |
| T03 | `MANUAL_VELOCITY` | 手动速度 | 前进、后退、横移、旋转和驻停点动 | 指挥控制台按钮、速度档位、速度参数 | 运动控制 |
| T04 | `SET_ALARM_CONFIG` | 设置报警配置 | 将报警时间、等级、音量、识别事件和报警区域作为结构化 JSON 同步给后端 | 报警配置窗口、GPS 围栏数据 | 报警服务 |
| T05 | `AUDIO_CONTROL` | 语音控制 | 启停 PC 与机器狗之间的音频通道 | 发送声音/接收声音按钮、通道动作 | 音频服务 |


所有任务使用《json格式文件.md》中的统一外层结构。`task_type` 决定任务类型，`payload` 决定该任务的具体参数。`AUDIO_CONTROL` 只传输通道控制 JSON，不传输连续音频数据；

任务要点：

- `GOTO_KEYPOINT`：由计划管理页面“下发计划”按钮触发，`waypoints` 可以有一个或多个元素，后端按数组顺序导航；
- `STOP_TASK`：由停止操作触发，停止当前导航或任务，并使运动速度归零；
- `MANUAL_VELOCITY`：由指挥控制台的前进、后退、左右移、左右转和驻停按钮触发，必须使用 `duration_ms` 超时保护；
- `SET_ALARM_CONFIG`：由报警参数窗口触发，正式格式为结构化 JSON，包含全局参数、人员/车辆事件和区域顶点；
- `AUDIO_CONTROL`：由发送声音/接收声音按钮触发，只控制音频通道启停，不承载连续音频数据。


## 3. Qt 前端功能枚举（非 Zenoh 任务）

本节列出 Qt 中实际存在、但不产生任务 `task_type` 的前端功能。它们属于页面操作、本地文件处理、媒体显示或状态展示，后端不需要为这些功能额外订阅任务 key。

| 编号 | Qt 功能 | 界面入口/对象 | 功能说明 | 数据来源或结果 | 是否发布任务 |
|---|---|---|---|---|---|
| F01 | 页面切换 | `btnPage1`～`btnPage4` | 在计划管理、综合态势、作业状态、查询与导出页面之间切换 | Qt 页面状态 | 否 |
| F02 | 机器狗选择与集群管理 | `btnRobotSelector` | 打开集群管理窗口，选择当前机器狗；切换后同步切换设备编号和摄像头源 | `config/robot_fleet.yaml`、RobotManager | 否 |
| F03 | 摄像头画面预览 | 综合态势/人脸识别画面区域 | 周期读取当前机器狗的最新画面并显示；配置了 `camera_rtsp_url` 时使用 RTSP | RTSP 或 `DemoFrameProvider` | 否；画面不经过任务 JSON |
| F04 | 摄像头画面全屏/还原 | `pushButton_11`、`pushButton_12`、`pushButton_13`、`pushButton_14` | 控制两路画面窗口全屏和还原 | Qt 窗口状态 | 否 |
| F05 | 新建计划 | `p1_btn0` | 打开计划编辑窗口，填写计划编号、标题、算法、时间、执行机器狗和目标点 | 本地 `PlanData` | 否；点击“下发计划”才产生 `GOTO_KEYPOINT` |
| F06 | 查看历史计划 | `p1_btn1` | 从计划目录选择 JSON 文件并以只读窗口查看 | `plans/*.json` | 否 |
| F07 | 修改计划 | `p1_btn2` | 编辑已有计划并保存回本地计划文件 | `PlanData`、计划 JSON 文件 | 否 |
| F08 | 地图选点与路点排序 | 计划编辑窗口中的地图选择 | 在地图上选择关键点，增加、删除、上移、下移并清空路点；最终形成 `waypoints` 数组 | 地图选点、关键点本地数据 | 否；数据随后被 `GOTO_KEYPOINT` 使用 |
| F09 | 本地计划文件管理 | 计划编辑/保存流程 | 保存和加载计划 JSON，保存内容包括计划信息、目标点、录制路径 ID 和指定机器狗 | `plans/` 目录 | 否 |
| F10 | 计划执行界面更新 | “下发计划”后的页面逻辑 | 更新当前计划、目标点表格、执行状态标签和巡检记录；页面更新本身不是任务 | Qt 内存状态、本地巡检记录 | 部分；仅导航发布部分是 `GOTO_KEYPOINT` |
| F11 | 作业状态展示 | 作业状态页面 | 显示当前设备编号、任务文本、控制日志、目标点完成情况和设备状态表 | Qt 状态缓存、RobotDataCache、本地任务记录 | 否 |
| F12 | 在线状态和机器人状态显示 | 页面状态指示灯、设备状态表 | 根据 Zenoh 状态缓存更新在线/离线显示；这是订阅状态后的 UI 刷新，不是 Qt 发布任务 | `RobotDataCache` 状态消息 | 否；属于状态订阅结果 |
| F13 | 报警参数窗口和区域编辑 | `btnParamAdjust`、`AlarmConfigDialog` | 编辑报警等级、时间、音量、次数、冷却、是否开启人员/车辆事件和设定报警区域；确认时形成 T04 | 本地表单、围栏文件、结构化报警 JSON | 发布 `SET_ALARM_CONFIG` |
| F14 | 实时报警接收与报警日志 | Zenoh 报警事件回调、报警日志表格 | 接收报警事件，去重后写入巡检记录并刷新报警日志表格 | `RobotDataCache` 报警事件 | 否；属于接收事件 |
| F15 | 报警画面快照 | 报警事件处理流程 | 报警发生时读取当前摄像头帧，保存 PNG 快照并关联巡检记录 | `records/<record_id>/snapshots/` | 否 |
| F16 | 主控本地录像 | 下发计划后自动开始，停止任务或导航结束后停止 | Qt 主控通过 FFmpeg 拉取 RTSP，按 60 秒分段写入本地 | `camera_rtsp_url`、`recordings/` | 否；不使用录像任务 |
| F17 | 录像会话刷新与导出 | `btnRefreshSessions`、`btnBrowseExportDir`、视频导出按钮 | 扫描本地录像会话，选择导出目录，并合并分段视频 | `recordings/`、FFmpeg | 否 |
| F18 | 巡检历史查询 | `pushButton_3`、筛选/清除筛选按钮、历史表格双击 | 加载、筛选、查看巡检记录和详情 | `records/inspection.json` 等本地文件 | 否 |
| F19 | 巡检报告导出 | `pushButton_export` 或详情窗口导出 | 将选中的巡检记录生成 PDF 报告 | 本地巡检记录、报警快照、视频会话信息 | 否 |
| F20 | 用户切换和管理员管理 | 用户切换、管理员入口 | 登录用户切换、权限界面和用户管理 | SessionManager、UserManager | 否 |
